= Browser streaming contract
:page-type: architecture
:page-status: current
:summary: Browser decoding, media import, streaming A/V encoding, byte-range transport, and bounded buffer-driven presentation.
:nav-order: 40

The browser player and converter use the canonical Rust codec through WebAssembly. JavaScript handles
file and network I/O, cancellation, playback queues and clocks, browser audio, presentation, and the
FFmpeg ingest boundary for non-Avelune media.

[#browser-wasm-surface]
== WASM surface

The decoder API accepts incremental container bytes and returns validated stream metadata and decoded
outputs. Its important operations are conceptually:

[source,text]
----
avelune_abi_version() -> 0x0002_0000
decoder_create() -> handle
decoder_destroy(handle)
input_reserve(handle, len) -> ptr
decoder_push(handle, len)
decoder_finish_input(handle)
decoder_seek_reset_epoch(handle, epoch_id)
decoder_pop_video(handle)
decoder_pop_audio(handle)
----

The ABI exposes the Rust-validated front index, stream descriptors, indexed epoch byte ranges, and
stream IDs on decoded outputs. JavaScript does not independently implement Avelune packet framing,
CRC checks, stream routing, or codec reference-state semantics.

`decoder_finish_input` is required at an indexed-range boundary. Transport EOF alone does not prove
that the parser stopped on a complete packet.

The browser also exposes A/V encoder APIs. The media importer uses the streaming variant:

[source,text]
----
av_stream_encoder_create(...) -> handle
av_stream_encoder_video_frame_ptr(handle) -> ptr
av_stream_encoder_push_video_frame(handle)
av_stream_encoder_audio_reserve(handle, sample_count) -> ptr
av_stream_encoder_push_audio(handle, sample_count)
av_stream_encoder_ready_epochs(handle) -> count
av_stream_encoder_take_epoch(handle)
av_stream_encoder_epoch_ptr(handle) / av_stream_encoder_epoch_len(handle)
av_stream_encoder_finish(handle)
av_stream_encoder_prefix_ptr(handle) / av_stream_encoder_prefix_len(handle)
av_stream_encoder_destroy(handle)
----

Complete encoded epochs can therefore leave WASM as soon as they are ready. Finalization returns the
container prefix/front index after the encoder knows the complete epoch table. A non-streaming A/V
encoder API also exists for small inputs and tests; it is not the ordinary-media import path.

[#browser-artifacts]
== Scalar and SIMD128 artifacts

`build-wasm.sh` produces separate `avelune-scalar.wasm` and `avelune-simd128.wasm` modules. `auto`
tries SIMD128 first and falls back to scalar when the SIMD module cannot be loaded. Both implement
the same codec/container semantics.

WebGPU is separate from this choice. In the browser player it is a presentation backend; selecting
WebGPU does not replace the ALV1/ALA1 WASM decoder.

[#browser-byte-sources]
== Avelune byte sources

Playback uses one range-source contract for HTTP and local files.

For HTTP, every requested media range must:

* return status `206`;
* return a parseable `Content-Range` matching the exact requested first and last byte;
* report a consistent total source size when one is supplied;
* return the expected `Content-Length` when that header is present;
* deliver exactly the indexed byte count, neither shorter nor longer.

A cross-origin source must also allow the browser request through CORS, including the `Range` request
header as required by the deployment.

Local `Blob`/`File` playback uses `Blob.slice()` in bounded chunks and exercises the same indexed
epoch decode path without uploading the file.

[#browser-media-import]
== Ordinary-media import

The demo bundles a single-threaded FFmpeg WebAssembly build for foreign container/codec ingest. It is
loaded only when conversion is requested. FFmpeg is an input boundary; ALV1, ALA1, and AVL encoding
remain in the Avelune WASM module.

The conversion path is:

[source,text]
----
File -> FFmpeg WORKERFS input
     -> raw yuv420p frame sink ----\
                                 Avelune streaming A/V encoder -> completed AVL epochs
     -> interleaved s16 PCM sink -/                              -> OPFS when available
                                                                  -> final AVL File
----

The original `File` is mounted through Emscripten WORKERFS rather than copied into one large
`ArrayBuffer`. FFmpeg writes raw video and PCM to bounded custom devices. JavaScript feeds complete
video frames and aligned PCM blocks to the streaming Avelune encoder; it does not materialize a full
Y4M or PCM intermediate.

When Origin Private File System (OPFS) synchronous access is available in the worker, completed
compressed epochs are spooled there. Otherwise the converter retains completed *compressed* epoch
chunks in memory until final assembly. The fallback therefore preserves streaming raw-media ingest
but does not provide storage-bounded compressed output for arbitrarily large conversions.

The final result is assembled from the small front-index prefix plus the encoded epoch body and is
returned as a browser `File`. Conversion is local to the page; the demo does not upload source media.

[#browser-generations]
== Decode and playback generations

Starting a load or epoch decode creates a new decoder generation and invalidates the previous one.
This check supplements `AbortSignal` transport cancellation. A stale source that ignores cancellation
is stopped before its next bytes can enter the reset WASM decoder.

Each play/resume/seek/replay operation also owns a distinct JavaScript playback buffer. Cancelling an
older operation can finish its producer later, but that producer can only mark its own queue complete;
it cannot make a newer seek/replay generation appear decoded or ready.

An epoch decode transaction is:

. reset the canonical session for the expected indexed epoch ID;
. stream arbitrary byte fragments into the decoder;
. drain decoded outputs into the active playback queues, waiting only for bounded high-water
  backpressure rather than presentation timestamps;
. explicitly finalize input;
. accept success only if the parser/session is complete and semantically valid.

The media importer runs FFmpeg synchronously inside a dedicated worker. Cancelling a conversion
terminates that worker, which also stops the current FFmpeg run and Avelune encoder instance.

[#browser-presentation]
== Presentation and buffering

Decode throughput and presentation timing are deliberately separate. The producer decodes consecutive
indexed epochs ahead into bounded audio/video queues. It may pause when a queue reaches its decoded
high-water mark, but decoded callbacks never sleep until a frame's wall-clock presentation time.
This preserves cross-epoch decode cushion under ordinary HTTP/WASM jitter.

For A/V content, audio is the master playback clock. Playback waits for a decoded prebuffer before
starting. PCM is then submitted ahead of the clock at its exact media timestamp. When the browser can
create an `AudioContext` at the stream sample rate and supports `AudioWorklet`, Avelune uses one
continuous worklet PCM timeline keyed to absolute WebAudio frames. Timestamp gaps remain gaps; the
worklet does not concatenate packets merely because they arrived next to each other.

When the requested sample rate cannot be used by the context, or `AudioWorklet` is unavailable, the
fallback schedules `AudioBufferSourceNode` buffers at the same exact timeline positions and lets
WebAudio perform the rate conversion. The fallback must not clamp a missed start time to
`currentTime`. A packet or worklet chunk that reaches the output after its presentation deadline is
an explicit underrun/fault, not silently shortened media.

Video presentation independently consumes the newest decoded frame due at the audio clock (or the
wall clock for video-only media). A slow renderer can therefore drop obsolete due frames without
stalling decoder progress or moving the audio timeline.

Pause, seek, replay, reload, and playback errors cancel pending decode/output work and start with new
queue/clock state. The demo inspector exposes the selected audio-output mode, contiguous queued audio,
furthest decoded-audio extent, queued video, decoder-late packets, worklet-late frames, and underrun
count so starvation is observable rather than inferred from audible glitches.

Canvas2D and WebGPU are presentation implementations only; they do not change codec semantics.
WebGPU textures and pipelines are reused while dimensions remain unchanged.

[#browser-validation]
== Playback validation

The regular browser/WASM gate includes:

* delayed HTTP Range delivery across indexed epochs;
* pause/resume, seek while playing, completion, and replay;
* explicit scalar-WASM/Canvas2D playback in addition to automatic artifact/renderer selection;
* sample-exact q1 tone, speech-like, and music-like A/V decode through scalar and SIMD128 artifacts,
  followed by zero-silence/zero-late-frame PCM-timeline reconstruction;
* exact q1 A/V encode/decode matrices with 1, 2, 4, and 8 second epoch durations;
* a 30-minute virtual playback soak asserting bounded audio/video/worklet queues and zero underruns;
* deterministic Canvas2D and WebGPU renderer resource-path tests, including texture reuse and cleanup;
* explicit zero-underrun and zero-late-output assertions for the jittered Chromium playback path.

The current hosted Linux Chromium runner does not expose `navigator.gpu`, so the deterministic WebGPU
renderer test is logic/resource-lifecycle coverage rather than hardware-GPU evidence. GPU-backed
WebGPU presentation and subjective listening remain environment-specific validation; a headless
`--disable-gpu` Chromium run must not be treated as evidence for either.
