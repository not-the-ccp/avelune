= Reference implementation policy
:page-type: development-guide
:page-status: current
:summary: The policy and priorities for keeping the Rust reference/research implementation readable, safe, and aligned with the normative specification.
:nav-order: 70

The Rust implementation under `impl/rust/` is a reference/research implementation.

[#avl-reference-priorities]
== Priorities

. match the normative specification;
. be readable enough to audit against the specification;
. reject malformed input deterministically and safely;
. support conformance and experimentation;
. remain reasonably usable as a POC.

[#avl-reference-performance-boundary]
== Performance boundary

Peak encode/decode performance is *not* a design requirement for this implementation. Do not add SIMD, threading, GPU-specific code, aggressive buffering, or opaque performance tricks merely to make benchmark numbers look better. Such work belongs in `prod/` unless an optimization is both semantics-preserving and clearly improves the reference implementation without obscuring it.

[#avl-reference-format-feedback]
== Format feedback

If implementation experience disproves a codec assumption, revisit the format design. Do not change the spec just to mirror an implementation accident, and do not silently work around an architectural format flaw in code.
